# `bruno` skill: Bruno OpenCollection as the API source of truth

Date: 2026-11-09 · Status: approved design, pending spec review

## Goal

Replace the four-skill api-doc chain with one skill, `bruno`. The Bruno OpenCollection under a
service repo's `bruno/` becomes the source of truth for every HTTP endpoint: the runnable request
plus the `docs:` markdown inside each request file. `docs/api/*.yaml` is retired.

```
before:  api-spec ──► docs/api/*.yaml ──► open-collection · openapi-doc · confluence-api-doc
after:   bruno    ──► bruno/<domain>/<endpoint>.yml (http + runtime + docs:)
```

## Decisions (from brainstorming)

| # | Question | Decision |
| --- | --- | --- |
| 1 | Which skills are removed | `api-spec`, `open-collection`, `openapi-doc`, `confluence-api-doc` |
| 2 | What moves into `bruno` | Authoring/validation and the Go drift check. Confluence publishing is dropped entirely. |
| 3 | Contract format | Hand-authored `docs:` markdown with a fixed layout, modelled on `bruno-api-documents/Core System Services/Account/suspend/suspend-accounts.yml` |
| 4 | Where the source of truth lives | `bruno/` inside the service repo. The central `bruno-api-documents` repo is a downstream copy, out of scope. |
| 5 | Error table | `Status \| Response Code \| Error Code \| Error Messages \| Description` (common-lib) |
| 6 | Existing `docs/api/` repos | A `Migrate` mode backed by a deterministic `migrate.py` |
| 7 | Script layout | Approach A: one script per mode, sharing one parser (`docsparse.py`) |
| 8 | Audience | `docs:` carries no ticket IDs, decision IDs, AC-IDs, `## Contract source` sections or repo-internal paths. The reference file violates this and is not a model for it. |

Measured scope of migration (local checkouts, 2026-11-09): 16 service repos with
`docs/api/_meta.yaml`, about 240 endpoints; 14 of them already have a `bruno/` generated by
`open-collection` in the old layout.

## Out of scope

- Publishing to Confluence, or syncing `bruno/` into the central `bruno-api-documents` repo.
- Any OpenAPI, Postman or curl conversion. `bruno/openapi.yaml` files found in service repos are
  left untouched and reported as warnings.
- Version bump and release. Removing four skills is a breaking change, so a later bump is major,
  done only when the user asks.

## Collection layout

```
bruno/
├── opencollection.yml       info.name + docs: (service level)
├── environments/            local.yml · sit.yml (init-project template naming)
└── <domain>/
    ├── folder.yml           info{name,type: folder,seq} + request.auth/headers + optional docs:
    └── <endpoint>.yml       one endpoint = the source of truth for that endpoint
```

Request file top-level order: `info → http → runtime → settings → docs`. `examples` is never
emitted.

### Collection-root `docs:` (`opencollection.yml`)

```markdown
## Overview
<service purpose>

## Field Information          ← optional; shared enums
### <Enum Name>
| Code | Description |

## Error Response Body        ← required; the common-lib body, documented once
| Field Name | Type | Mandatory | Description | Possible Value |
| responseCode | String | Yes | ... | `"001"` |
| errorCode    | String | Yes | ... | `"<PREFIX>-1002"` |
| errorMessage | String | Yes | ... | `"Invalid field format: customerId"` |

## Common Error Responses     ← required; may hold zero rows
| Status | Response Code | Error Code | Error Messages | Description |
```

Domain prose that used to live in `_meta.domains.<d>` goes to that folder's `folder.yml` `docs:`.

### Request `docs:` (`<domain>/<endpoint>.yml`)

```markdown
## Purpose
<prose>

## Request
### Endpoint
`POST /v1/accounts/{accountId}/suspend`
### Auth
`None`
### Headers                  ← optional, field table
### Path Parameters          ← required when the path has {param}
### Query Parameters         ← optional
### Body (JSON)              ← optional, field table
### Example                  ← JSON block; required when Body (JSON) is present

## Response
### HTTP Status: 200         ← one per success status; prose allowed before the table
| Field Name | Type | Mandatory | Description | Possible Value |
### Example
### Error Responses          ← endpoint-specific errors only
| Status | Response Code | Error Code | Error Messages | Description |

## <free section>            ← e.g. Business Logic, Notes, SIT; ignored by the parser
```

A non-common-lib error body (a partner contract) is documented as its own
`### HTTP Status: <4xx/5xx>` section with a field table.

### Table rules

- Every field table (Headers, Path, Query, Body, Response) has exactly the columns
  `Field Name | Type | Mandatory | Description | Possible Value`.
- `Type` ∈ `String`, `Number`, `Boolean`, `Object`, `Array`. `Mandatory` ∈ `Yes`, `No`.
- Nesting is a dot-path: `data.accountId`, `items[].citizenId`. Every nested row has a parent row
  whose Type is `Object` (for `.`) or `Array` (for `[].`).
- Escaped pipes (`\|`) inside a cell are part of the cell text.
- Error table columns are exactly `Status | Response Code | Error Code | Error Messages | Description`.
  A common-lib code (`<PREFIX>-NNNN`, 2–3 uppercase letters and four digits) requires a
  Response Code that maps to Status per the common-lib table
  (`init-project/assets/template/.kiro/steering/errors.md:29`):
  `001`→400, `002`→400, `003`→404, `004`→409, `005`→503, `006`→504, `999`→500.
  A partner contract may leave Response Code blank.

## Modes

Selection order (the user can always override):

1. `docs/api/_meta.yaml` exists → **Migrate** (confirm with the user before writing, since every
   other mode would read a stale `bruno/`)
2. Request asks for a draft / design before code → **Draft**
3. Request asks for drift / "does the code match" → **Drift**
4. Request asks to validate / check → **Validate**
5. No `bruno/opencollection.yml` → **Generate**
6. Otherwise → **Update**

| Mode | Writes | Input | L1 | L2 fresh-eyes | L3 completeness |
| --- | --- | --- | --- | --- | --- |
| Draft | yes | intent only (ticket, `docs/knowledge/`, user); never code; no `## Business Logic` | `brunocheck.py` | skipped | every AC that needs an endpoint has one |
| Generate | yes | intent + existing code | `brunocheck.py` | offered, default yes | every intended endpoint exists |
| Update | yes | requested delta, or built code (sync-back) | `brunocheck.py` | offered | no endpoint dropped |
| Validate | no | `bruno/` | `brunocheck.py` | offered | as Update |
| Drift | no | Go source + `bruno/` | `driftcheck.py` | offered | both route and request inventories compared |
| Migrate | yes, then removes `docs/api/` | `docs/api/` + existing `bruno/` | `migrate.py` round-trip, then `brunocheck.py` | offered, sampled | every `docs/api` endpoint has a request with `docs:` |

Update preserves user-authored runnable parts: `http.headers`, `http.auth`, `runtime`, environment
values. Draft runs L1 + L3 only, matching the old `api-spec` Draft rule.

Verify-loop rule (unchanged from the old skills): on exit 1, fix the real defect and re-run; stop
and escalate after about three rounds without progress; never fake a green run.

## Components

### `assets/docsparse.py`

Pure parser, no I/O beyond reading files. Public functions:

- `parse_request(path) -> dict` with `method`, `path`, `auth`, `tables` (`headers`, `path`,
  `query`, `body` → list of rows), `request_example`, `responses` (status → `{fields, example}`),
  `errors` (rows), `http` (the runnable block), `runtime`, `order` (top-level key order).
- `parse_collection(root) -> dict` with the root `docs:` sections, folders and requests.
- `field_tree(rows) -> dict` turning dot-path rows into a nested tree.

Parse failures raise a typed error carrying `file:line`, which `brunocheck.py` reports as ERROR.

### `assets/brunocheck.py <bruno-root>`

Exit 0 on no ERROR, 1 otherwise. NOTE lines end with `needs fresh-eyes` and feed L2.

| Rule | Check |
| --- | --- |
| K1 | every `.yml` parses; request top-level order is `info → http → runtime → settings → docs` |
| K2 | `### Endpoint` method and path match `http.method` / `http.url` (`{id}` ↔ `:id`, `{{baseUrl}}` stripped) |
| K3 | path params agree across the path, the Path Parameters table and `http.params` with `type: path` |
| K4 | field tables have the exact columns; Type and Mandatory values are in their enums; every dot-path has its parent |
| K5 | every Example parses as JSON; each of its key paths has a row in the matching table; every `Yes` row is present whenever its parent is present; `http.body.data` has the same key-path set as the Body Example (values may differ, `{{var}}` allowed) |
| K6 | error tables have the exact columns; common-lib codes carry a Response Code that maps to Status |
| K7 | `runtime.scripts` has at least one `type: tests` script that references `res.status` |
| K8 | every `{{var}}` (except `{{process.env.*}}`) is defined in `environments/`; secret-looking names have `value: ""` |
| K9 | every domain directory has a `folder.yml`; `seq` is unique within each folder |
| K10 | Audience: ERROR on repo-internal paths (`internal/`, `docs/knowledge/`, `*.go:NN`), `AC-NNN`, `D-NN`, a `## Contract source` heading; NOTE on any `XX-NNNN` token that is not declared in an Error Code column (a possible ticket key; regex cannot tell `GI-3467` from `ACC-1001`) |
| K11 | `opencollection.yml` `docs:` has `## Error Response Body` and `## Common Error Responses` |

Logic for K6 is ported from `api-spec/assets/apispeccheck.py` (`RESPONSE_STATUSES`,
`check_errors`). K2, K3 and K8 are ported from `open-collection/assets/colcheck.py`.

### `assets/migrate.py <docs/api> <bruno-root>`

Deterministic converter. It never deletes anything.

- Matches each `docs/api/<domain>/<endpoint>.yaml` to a request by method + normalized path, not
  by file name. Unmatched spec endpoint → creates `<domain>/<endpoint>.yml` with `info`, `http`
  from the spec, a default status test and `settings.encodeUrl: true`. Unmatched existing request →
  left untouched, reported as a warning.
- Rewrites only `docs:` and the top-level order of a matched request. `http` and `runtime` are kept
  as-is; a request with no `type: tests` script gets `test("status is <first success status>")`.
  `http.body.data` is kept when present, else set from `request_body.example`.
- Field mapping: `M`→`Yes`, `O`→`No`; Description = `description` plus ` ` + `remark` when the
  remark is non-empty; Possible Value = `example` as JSON in backticks, empty for object refs; a
  field with `object: X` becomes an `Object`/`Array` row followed by X's rows under `name.` or
  `name[].` (recursive).
- Responses with status < 400 → `### HTTP Status: N`. An error response whose fields are exactly
  `responseCode`, `errorCode`, `errorMessage` is dropped (documented once at the root); any other
  error body becomes its own `### HTTP Status: N` section.
- `business_logic` → `## Business Logic`; `notes` → `## Notes`; `errors` → `### Error Responses`;
  `covers_ac` dropped. The old `yaml2md.py` Audience filter (`audience_text`, `audience_notes`) is
  ported and applied to prose; K10 catches what it misses.
- `_meta.yaml`: `overview` → `## Overview`; `field_info` → `## Field Information`;
  `common_errors` → `## Common Error Responses`; the standard `## Error Response Body` table is
  written; `domains.<d>.seq` → `folder.yml` `info.seq`; `domains.<d>.title/description` →
  `folder.yml` `docs:`; `extra_endpoints` without a request file → a minimal request.
- Round-trip: after writing, re-parse every request with `docsparse.py` and compare against the
  source YAML flattened to dot-paths the same way: field set (name, type, mandatory) per table and
  error rows (status, responseCode, code). Any mismatch → exit 1 listing each endpoint.

The SKILL instructs the agent to remove `docs/api/` only after `migrate.py` and `brunocheck.py`
both exit 0, in the same change, so it stays recoverable from git.

### `assets/driftcheck.py <bruno-root> --src <go-root>`

Port of `openapi-doc/assets/speccheck.py`. The Go scanning is unchanged; the spec loader reads
`bruno/` through `docsparse.py`. Checks: route coverage both ways, and per matched endpoint the
Body and success Response fields against Go structs (presence, `Mandatory` vs struct tags,
confident type mismatches). Unconfident matches become NOTEs. Writes nothing; the agent reconciles
through Update-from-code.

| 7 | packages still valid | the five package validators in `AGENTS.md` and `claude plugin validate .` pass |

## Risks

- Markdown tables are more fragile than YAML. K4 turns every malformed row into an L1 ERROR.
- Not verified: whether editing a request in the Bruno desktop app reformats `docs:`. If it does,
  K-rules will flag the result on the next run rather than silently accept it.
- K10 cannot separate ticket keys from error codes by pattern, so that part is a NOTE for L2, not
  an ERROR.
