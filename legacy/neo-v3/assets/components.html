Component Library

Living style guide — ทุก component ที่ใช้ในเอกสารชุดนี้ พร้อม HTML pattern + เมื่อไหร่ใช้

🎯
หน้านี้คือ "สเปก" ที่ specialist (BA/Architect/QA) ใช้ generate HTML. แต่ละ component ใช้ class + data-* ที่ตั้งชื่อชัด ดังนั้น หน้า content ใหม่ = แค่ semantic HTML โดย shared assets/css/styles.css + assets/js/app.js (link ภายนอก) จัดการ look + interactivity ให้ · แยก asset ออกจาก content โดยตั้งใจ — เวลา AI/tool อ่านหน้า doc มันอ่านเฉพาะเนื้อหา ไม่ต้องอ่าน CSS/JS (ประหยัด token) · sidebar มาจาก assets/js/nav.js (render โดย JS) · mermaid โหลดจาก CDN · ดูวิธีใช้เต็มใน references/html-output.md

0 · Page shell

ทุกหน้าเริ่มจาก _shell.html ใน bundle: <html data-asset-prefix="…"> (root="", ลึก 1 ชั้น="../") → <link> CSS ภายนอก + inline FOUC script (key ds-theme ตรงกับ app.js) ใน <head> → .topbar (mobile) → .layout [.sidebar (ว่าง) + .main + .toc] → mermaid CDN → nav.js → components.js → app <script>. Sidebar ไม่ hardcode — ปล่อย <aside class="sidebar"></aside> ว่างไว้ แล้ว app.js (renderNav) สร้างจาก window.DOCS_NAV ใน assets/js/nav.js · TOC + active-link ตั้งอัตโนมัติ

<html lang="th" data-theme="light" data-asset-prefix="{{ASSET_PREFIX}}">
<head>
  <link rel="stylesheet" href="{{ASSET_PREFIX}}assets/css/styles.css">
  <script>/* theme-before-paint กัน FOUC — key: ds-theme */</script>
</head>
<div class="layout">
  <aside class="sidebar"></aside> <main class="main">…</main> <aside class="toc">…</aside>
</div>
<script src="https://cdn.jsdelivr.net/npm/mermaid@11.4.1/dist/mermaid.min.js"></script>
<script src="{{ASSET_PREFIX}}assets/js/nav.js"></script>
<script src="{{ASSET_PREFIX}}assets/js/components.js"></script>
<script src="{{ASSET_PREFIX}}assets/js/app.js"></script>

เพิ่ม usecase ใหม่ = แก้ nav.js ที่เดียว (ไม่ต้องไล่แก้ sidebar ทุกหน้า). ถ้าจะ hardcode sidebar แทน (B1 fallback) ใส่ .nav-group ลงใน .sidebar ตรงๆ ได้ — renderNav ตรวจเจอแล้วข้ามให้

เมื่อไหร่ใช้: แสดงสถานะ (Ready/Blocked/Pending) และ tag (priority, JIRA). status เขียนเป็น <status-badge status="…"> (label derive จาก status, กัน drift) · chip ยังเป็น <span class="chip"> (ไม่มีอะไรให้ derive)

2 · Callouts

เมื่อไหร่ใช้: เน้นข้อความสำคัญ. เขียนเป็น <callout-box kind="…"> (โค้ดด้านล่าง) — kind = note / success / warning / pending / blocked, icon+สี derive ให้

ℹ️
note — ข้อมูลทั่วไป / บริบท
✅
success — สิ่งที่พร้อม / ผ่านแล้ว
⚠️
warning — ข้อควรระวัง / สถานะ draft
⏳
pending — รอ decision / ขึ้นกับ upstream
⛔
blocked — ติด blocker, ทำต่อไม่ได้
<callout-box kind="blocked"><b>Blocker:</b> …</callout-box>
<callout-box kind="note" ico="🎯">custom-icon note</callout-box>

การ์ด callout 5 แบบด้านบนคือผลลัพธ์ของ <callout-box> — icon derive จาก kind เขียนครั้งเดียวที่ kind= สี+icon มาเอง (กัน icon ผิด kind) · ใส่ ico="…" เพื่อ override glyph ได้ · <ac-card>/<tc-card> emit blocked callout เองอยู่แล้ว

3 · Collapsible card + Given/When/Then

เมื่อไหร่ใช้: AC / TC ที่กาง-พับได้. data-status/data-subop/data-priority/data-traces ใช้สำหรับ filter. คลิกหัวเพื่อ toggle · AC เขียนเป็น <ac-card> (โค้ดด้านล่าง) — element จะ expand เป็นโครง .card นี้ให้ (badge/chip/chevron/label/field-row derive จาก attribute); TC เขียนเป็น <tc-card> (โค้ดด้านล่าง)

การ์ดด้านบนคือผลลัพธ์ที่ <ac-card> render ออกมา (โครง .card เดิม) · status เขียนครั้งเดียวที่ status= → is-ready/data-status/badge derive ตามทั้งหมด · prose ใส่ inline <b>/<code> ได้ใน <g>/<w>/<t>

<tc-card id="TC-002" status="ready" priority="p1" traces="AC-002"
         jira="PROJ-123" endpoint="POST /v1/accounts" label="open account">
  <g>a savings product exists</g><a>denomination = THB</a>
  <w>an account is opened</w><t>opened successfully</t>
  <req>{ "denomination": "THB" }</req>
  <res>HTTP 200
{ "status": "OPEN" }</res>
  <steps><step>call <code>POST /v1/accounts</code></step><step>assert 200</step></steps>
  <expected>HTTP 200, status = OPEN</expected>
  <precond>TC-001 must pass</precond>
</tc-card>

<tc-card> render เป็นโครง .card เดียวกับ AC + เพิ่ม Endpoint row, Request/Response .tabs (หรือ .code เดี่ยวถ้ามี JSON ฝั่งเดียว) และ Test Steps <ol> · เขียน GWT ลำดับ G-A-W-T (<a> = AND) · blocked TC ใส่ status="blocked" + <blocker> แล้ว element derive data-tags="blocked" + แถว AC Status ให้

7 · Data table (sortable)

เมื่อไหร่ใช้: ข้อมูลตาราง. ใส่ data-sortable เพื่อให้คลิกหัวคอลัมน์เรียงได้ (auto numeric/text) · หัวตาราง sticky

A-15Blocked

<ac-summary>
  <ac ref="AC-001" subop="Create account" rule="BR-01 unique name"></ac>
  <ac ref="AC-002" rule="BR-02 valid denomination" blocker="GI-90"></ac>
</ac-summary>

AC Summary เขียนเป็น <ac-summary> + <ac ref=..> ต่อ AC — Scenario/Priority/Status/JIRA derive จาก <ac-card> ที่ ref ชี้ (drift ไม่ได้) · พิมพ์เองแค่ subop (ชื่อ sub-op; ไม่ใส่ = "—") + rule (short ref) · blocker="<dep>" เติม "(blocked by <dep>)" ให้ · render เป็น .table-wrap > .data-table[data-sortable] (ตารางทั่วไปด้านบนเขียนมือ — หน้านี้ไม่มี <ac-card> จริง)

<tc-summary>
  <tc ref="TC-001" suite="Product Configuration" precond="None"></tc>
</tc-summary>

<tc-deferred>
  <tc ref="TC-005" blocker="error code not finalized" upstream="FX-104"></tc>
</tc-deferred>

TC Summary / Deferred = pattern เดียวกับ <ac-summary> — Description/Traces/JIRA/Status derive จาก <tc-card> ที่ ref ชี้ · summary author แค่ suite (ไม่ใส่="—") + precond (ไม่ใส่="None") · deferred (เฉพาะ blocked) author blocker + upstream · ใช้ <tc> holder ร่วมกัน 2 element

<ac-summary> … </ac-summary>
<ac-total></ac-total>   <!-- Total Acceptance Criteria: 5 (Ready: 4 / Blocked: 1) -->

<ac-total> / <tc-total> (ว่างๆ วางใต้ตาราง summary) นับ <ac-card>/<tc-card> ทุกตัวในหน้าตาม status → บรรทัด "Total …: N (Ready/Blocked)" · เพิ่ม/แก้ card แล้วเลขอัปเดตเอง (drift ไม่ได้)
