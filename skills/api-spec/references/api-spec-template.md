# API Spec — custom-YAML content spec (the api-spec skill authors; the api-doc chain reads)

The **API spec is the source of truth for every HTTP endpoint** — authored **spec-first** (before the
code exists, or reconciled back from it), in a **custom YAML** whose schema mirrors a human API-doc
table. It lives in a **global, by-domain** tree at `docs/api/`. One endpoint = one file, reused across
every usecase that touches it. This is **not** OpenAPI — the schema carries M/O, Remark, and multi-flow
Business Logic natively (OpenAPI cannot without heavy `x-` extensions). Its L1 validator is
`apispeccheck.py` (this skill's `assets/`).

The downstream api-doc chain derives everything from this tree: `openapi-doc` verifies the Go code against
it (drift / sync-back), `open-collection` turns it into a runnable Bruno collection + generated `docs:`,
and `confluence-api-doc` publishes it as Confluence pages — all **without needing the code to exist**.

## Output location

```
docs/api/
  _meta.yaml                   # global: title · version · base_url · overview · field_info · common_errors · domains
  <domain>/<endpoint>.yaml     # one endpoint per file (domain = the resource group, e.g. account/, balance/)
  index.md                     # navigation INDEX — GENERATED by apispeccheck.py (never hand-edit)
  VERSION.md                   # changelog (hand-maintained markdown, newest section first)
```

`<domain>` is the resource group (lowercase, e.g. `account`, `balance`, `closure`); `<endpoint>` is a short
verb-noun stem (e.g. `create`, `get`, `list`, `update-state`). Mirror the route grouping.

## `_meta.yaml` (global metadata — one per service)

```yaml
title: Account Service API Documentation
version: "1.1"                  # service-level doc version (string; bump in VERSION.md too)
base_url: /
overview: |                     # prose, 1-2 sentences
  Account Service provides APIs for managing bank accounts. ...
field_info:                     # reference enums shared across endpoints (rendered in INDEX "Field Information")
  Account Type:
    - { code: S, description: Saving }
    - { code: D, description: Current }
common_errors:                  # errors every endpoint may return (rendered once, in INDEX)
  - { status: 400, code: INVALID_REQUEST, message: "...", description: "..." }
domains:                        # per-domain ordering + optional group prose for the INDEX
  Account: { seq: 10 }
  Alpha:   { seq: 80, title: "Alpha (Customer Inquiry)", description: "Proxied inquiry endpoints ..." }
extra_endpoints:                # optional — index-only rows that have no spec file (e.g. health probe)
  - { domain: Health, method: GET, path: /health, description: 'Liveness probe — returns {"status":"ok"}' }
```

## `<domain>/<endpoint>.yaml` (one endpoint)

```yaml
endpoint: Create                # display name (→ INDEX row, page title)
domain: Account                 # group (→ INDEX section, collection folder, Confluence parent)
method: POST                    # GET | POST | PUT | PATCH | DELETE
path: /accounts/account         # route template; path params in {brace} form
auth: None                      # auth scheme or None
covers_ac: [AC-001, AC-002]     # optional traceability hook — the AC-IDs this endpoint satisfies (used in a neo loop)
description: |                   # prose; markdown inline (`code`, **bold**, bullet lists) allowed
  Open a new account. ...
path_params:                    # optional — present when the path has {params}
  - { name: accountId, description: ..., type: String, mandatory: M, example: "uuid-v4", remark: "" }
query_params:                   # optional
  - { name: customer_id, description: ..., type: String, mandatory: M, example: "uuid-v4", remark: "..." }
request_body:                   # optional — POST/PUT/PATCH
  fields:
    - { name: customerId, description: ..., type: String, mandatory: M, example: "uuid-v4" }
  example: |                    # the request JSON, verbatim
    { "customerId": "uuid-v4", ... }
responses:                      # one or more — usually a single 2xx
  - status: 200
    description: OK             # the reason phrase → "Response (200 OK)"
    fields:
      - { name: status, description: ..., type: String, mandatory: M, example: "Success" }
      - { name: data,   description: Response payload, type: Object, mandatory: M, object: AccountResponse }
    objects:                    # nested object tables referenced by a field's `object:`
      AccountResponse:
        - { name: accountId, description: ..., type: String, mandatory: M, example: "uuid-v4" }
    example: |                  # the response JSON, verbatim
      { "status": "Success", "data": { ... } }
business_logic: |               # prose; preserve multi-flow / dispatch as **bold** sub-headed numbered lists
  **Common (both flows)**
  1. ...
errors:                         # endpoint-specific errors (the common ones live in _meta, not here)
  - { status: 400, code: INVALID_REQUEST, description: Required field missing or type mismatch }
notes:                          # OPTIONAL — cross-cutting notes ONLY; omit the key entirely when none
  - "an out-of-scope statement that applies to the whole endpoint"
```

### Field object rules (a row in any `*_params` / `request_body.fields` / `responses[].fields` / `objects.*`)
- Keys: `name` · `description` · `type` (String / Number / Boolean / Object / Array) · `mandatory` (**`M`** or
  **`O`** — never a boolean) · `example` · `remark`.
- **`example`** holds the **native value** (`"uuid-v4"`, `0`, `true`, `null`, `{}`) — quote strings that look
  numeric (`"001"`, `"1"`). It is rendered as JSON (`json.dumps`), so it round-trips exactly.
- **`object: <Name>`** marks a field that references a nested object table → its inline example is left empty
  and the renderer writes "See `<Name>` Object below"; define `<Name>` under the response's `objects:` map.
- **`remark`** is the field's element-specific note (enum values, a conditional like ``Required when
  `accountType="G"` ``, a format). This is where per-field notes live — **never** a separate notes blob.

### Error object rules (a row in `errors:` or `_meta.common_errors`)
- Keys: `status` · `code?` · `message?` · `description`. **`code` and `message` are both optional** — give a
  machine `code` (rendered backticked) and/or a human `message` (plain prose); the renderer emits whichever
  columns are populated. `_meta.common_errors` typically carries both.

### Notes discipline (keep docs low-noise)
A field's note → its `remark`. An element's mechanism → its `description` / `business_logic`. **Only a
genuinely cross-cutting** statement (an orchestrator boundary, an out-of-scope note for the whole endpoint)
goes in `notes:` — and `notes:` is **omitted entirely** when empty. Never dump a changelog here (→
`VERSION.md`); doc-vs-code drift is not a note either — it surfaces as an `openapi-doc` drift report.

## `index.md` (generated)
`apispeccheck.py` **regenerates `index.md`** from `_meta.yaml` + every `<domain>/<endpoint>.yaml` (overview,
Field Information tables, the by-domain endpoint table, common errors). **Never hand-edit it** — author the
YAML and re-run the validator.

## `VERSION.md` (changelog — hand-maintained)
Append a section per change, **newest first**:
```
## v<N> — <YYYY-MM-DD>
- **Endpoint(s):** <domain>/<endpoint>, ...
- **Change:** <what changed and why>
```
Changelog entries live **only** here — never as a note inside an endpoint file.

## Spec-first + sync-back
- **Spec-first:** author/update the endpoint YAML *before* the code is implemented, so the implementation has
  a contract to match. Downstream teams consume the spec (collection / Confluence) immediately, without
  waiting for the code.
- **Sync-back:** when code has drifted from the spec, run `openapi-doc` (Go ↔ this spec) to get a **drift
  report**, then reconcile the YAML to the intended contract (or, if the code is correct and the spec is
  stale, update the YAML to match) + log it in `VERSION.md`. A genuine design conflict (not small drift) →
  surface it for a human decision, never silently diverge.

## Verify (your L1 gate)
```
python3 <ASSET_DIR>/apispeccheck.py docs/api      # validates every endpoint YAML + regenerates index.md
# expect: PASS — 0 error(s)
```
`apispeccheck.py` checks: each endpoint file parses + has the required keys; `mandatory ∈ {M,O}`; every
`example`/`request_body.example`/`responses[].example` JSON parses; every `object:` reference resolves to a
defined `objects:` entry; `_meta.yaml` is well-formed; and `index.md` is in sync (it rewrites it). Fix every
error before returning `DONE`. Then self-check semantically — every endpoint the intent touches exists and
its request/response/errors match the intent's business rules + status codes.
