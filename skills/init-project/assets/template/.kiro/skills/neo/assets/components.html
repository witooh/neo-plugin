Component Library

Living style guide — every component used in this doc set, with its HTML pattern + when to use it

🎯
This page is the "spec" that specialists (BA/Architect/QA) use to generate HTML. Each component uses a clearly-named class + data-*, so a new content page = just semantic HTML while the shared assets/css/styles.css + assets/js/app.js (external links) handle look + interactivity · assets are split from content on purpose — when an AI/tool reads a doc page it reads only the content, not the CSS/JS (saves tokens) · the sidebar comes from assets/js/nav.js (rendered by JS) · mermaid loads from a CDN · see full usage in references/html-output.md

0 · Page shell

Every page starts from _shell.html in the bundle: <html data-asset-prefix="…"> (root="", 1 level deep="../") → <link> external CSS + inline FOUC script (key ds-theme matches app.js) in <head> → .topbar (mobile) → .layout [.sidebar (empty) + .main + .toc] → mermaid CDN → nav.js → components.js → app <script>. The sidebar is not hardcoded — leave <aside class="sidebar"></aside> empty and app.js (renderNav) builds it from window.DOCS_NAV in assets/js/nav.js · TOC + active-link are set automatically

<html lang="en" data-theme="light" data-asset-prefix="{{ASSET_PREFIX}}">
<head>
  <link rel="stylesheet" href="{{ASSET_PREFIX}}assets/css/styles.css">
  <script>/* theme-before-paint to prevent FOUC — key: ds-theme */</script>
</head>
<div class="layout">
  <aside class="sidebar"></aside> <main class="main">…</main> <aside class="toc">…</aside>
</div>
<script src="https://cdn.jsdelivr.net/npm/mermaid@11.4.1/dist/mermaid.min.js"></script>
<script src="{{ASSET_PREFIX}}assets/js/nav.js"></script>
<script src="{{ASSET_PREFIX}}assets/js/components.js"></script>
<script src="{{ASSET_PREFIX}}assets/js/app.js"></script>

Add a new usecase = edit nav.js in one place (no need to edit the sidebar on every page). To hardcode the sidebar instead (B1 fallback), put .nav-group directly into .sidebar — renderNav detects it and skips

1 · Status badges & chips

When to use: show status (Ready/Blocked/Pending) and tags (priority, JIRA). Write status as <status-badge status="…"> (the label is derived from status, preventing drift) · a chip stays a <span class="chip"> (nothing to derive)

Ready Blocked Pending   default P0 P1 GI-90 

<status-badge status="ready"></status-badge>   <!-- label derived: Ready -->
<span class="chip" data-tone="p0">P0</span>
<span class="chip" data-tone="jira">GI-90</span>

2 · Callouts

When to use: emphasize an important message. Write it as <callout-box kind="…"> (code below) — kind = note / success / warning / pending / blocked, icon+color are derived

ℹ️
note — general info / context
✅
success — something ready / passed
⚠️
warning — a caution / draft status
⏳
pending — awaiting a decision / depends on upstream
⛔
blocked — stuck on a blocker, cannot continue
<callout-box kind="blocked"><b>Blocker:</b> …</callout-box>
<callout-box kind="note" ico="🎯">custom-icon note</callout-box>

The 5 callout cards above are the output of <callout-box> — the icon is derived from kind, written once at kind= and color+icon follow (preventing a wrong-kind icon) · add ico="…" to override the glyph · <ac-card>/<tc-card> already emit their own blocked callout

3 · Collapsible card + Given/When/Then

When to use: a collapsible AC / TC. data-status/data-subop/data-priority/data-traces are used for filtering. Click the head to toggle · write an AC as <ac-card> (code below) — the element expands into this .card structure (badge/chip/chevron/label/field-row derived from attributes); write a TC as <tc-card> (code below)

AC-000example cardReadyP0▸
Given
the initial condition
When
the event occurs
Then
the expected result
Business Rule

<ac-card id="AC-000" status="ready" priority="p0" traces="TC-001" label="example card">
  <g>the initial condition</g>
  <w>the event occurs</w>
  <t>the expected result</t>
  <rule>the rule description</rule>
</ac-card>

The card above is what <ac-card> renders (the same .card structure) · status is written once at status= → is-ready/data-status/badge all derive from it · prose can include inline <b>/<code> in <g>/<w>/<t>

<tc-card id="TC-002" status="ready" priority="p1" traces="AC-002"
         jira="PROJ-123" endpoint="POST /v1/accounts" label="open account">
  <g>a savings product exists</g><a>denomination = THB</a>
  <w>an account is opened</w><t>opened successfully</t>
  <req>{ "denomination": "THB" }</req>
  <res>HTTP 200
{ "status": "OPEN" }</res>
  <steps><step>call <code>POST /v1/accounts</code></step><step>assert 200</step></steps>
  <expected>HTTP 200, status = OPEN</expected>
  <precond>TC-001 must pass</precond>
</tc-card>

<tc-card> renders the same .card structure as an AC + adds an Endpoint row, Request/Response .tabs (or a single .code when there is JSON on only one side) and Test Steps <ol> · write GWT in G-A-W-T order (<a> = AND) · a blocked TC adds status="blocked" + <blocker> and the element derives data-tags="blocked" + the AC Status row

7 · Data table (sortable)

When to use: tabular data. Add data-sortable so clicking a column header sorts it (auto numeric/text) · the table header is sticky

IDValueStatus
A-230Ready
A-15Blocked
A-3120Pending
 
<ac-summary>
  <ac ref="AC-001" subop="Create account" rule="BR-01 unique name"></ac>
  <ac ref="AC-002" rule="BR-02 valid denomination" blocker="GI-90"></ac>
</ac-summary>

AC Summary is written as <ac-summary> + an <ac ref=..> per AC — Scenario/Priority/Status/JIRA derive from the <ac-card> that ref points to (cannot drift) · you only type subop (the sub-op name; omitted = "—") + rule (short ref) · blocker="<dep>" appends "(blocked by <dep>)" · renders as .table-wrap > .data-table[data-sortable] (the plain table above is hand-written — this page has no real <ac-card>)

<tc-summary>
  <tc ref="TC-001" suite="Product Configuration" precond="None"></tc>
</tc-summary>

<tc-deferred>
  <tc ref="TC-005" blocker="error code not finalized" upstream="FX-104"></tc>
</tc-deferred>

TC Summary / Deferred = the same pattern as <ac-summary> — Description/Traces/JIRA/Status derive from the <tc-card> that ref points to · the summary author only writes suite (omitted="—") + precond (omitted="None") · deferred (blocked only) authors blocker + upstream · both elements share the <tc> holder

<ac-summary> … </ac-summary>
<ac-total></ac-total>   <!-- Total Acceptance Criteria: 5 (Ready: 4 / Blocked: 1) -->

<ac-total> / <tc-total> (empty, placed under the summary table) count every <ac-card>/<tc-card> on the page by status → the line "Total …: N (Ready/Blocked)" · add/edit a card and the number updates itself (cannot drift)

8 · Mermaid diagram

When to use: sequence / flowchart / graph (diagram-as-code). Put raw mermaid in .mermaid — JS renders + re-themes it for light/dark. No HTML tags in a label (the parser eats them); for a line break use &lt;br/&gt;

9 · Card-flow (gate chain)

When to use: a linear, clickable step sequence (pure CSS, not mermaid). Write it as <card-flow> + <step> (code below) — number + arrow are derived

1
Step 1
details
ERROR_CODE
2
Step 2 (blocked)
 
<card-flow>
  <step status="ready" href="#flow" tag="ERROR_CODE" detail="details">Step 1</step>
  <step status="blocked" href="#flow">Step 2 (blocked)</step>
</card-flow>

The chain above is the output of <card-flow> — the step number + the separating arrow between steps are derived (add/reorder steps without renumbering by hand) · status=ready/blocked · tag=code chip · detail=a secondary line (all optional)

10 · Trace matrix

When to use: an interactive AC↔TC map. Write it as an empty <trace-matrix></trace-matrix> (code below) — every row (AC + TC chips + status) is derived from the page's <ac-card>s · tbody th click-highlights a row

ACTestsStatus
AC-00xTC-0xxReady
AC-00yTC-0yyBlocked
 
<trace-matrix></trace-matrix>

The matrix above is hand-written for show (this page has no real <ac-card>) — in a real doc you write just an empty <trace-matrix></trace-matrix> and the element reads every <ac-card> on the page, building each row (AC id) + TC chips (from traces) + status badge (from status) itself — add/edit an AC without updating the table by hand (cannot drift)
